# E8 Windows daemon service boundary

`OwnMeshDaemon` has a fixed Windows SCM dispatcher. Its production service
image is deliberately not installed or advertised yet.

The current device enrollment, human configuration, and device-key storage are
bound to the interactive user's profile. Running the same executable as
`LocalSystem` changes those paths and keychain scope. An installer that copied
the user's profile, inherited its environment, or silently selected it from
`ProgramData` would change the ownership boundary and could make a privileged
service act with an ambiguous device identity. It is therefore prohibited.

## Current state

- The dispatcher uses the exact service name `OwnMeshDaemon` and reports SCM
  `START_PENDING`, `RUNNING`, `STOP_PENDING`, and `STOPPED` states.
- Windows E8 remains **OPEN**. There is no public daemon-service install,
  start, stop, status, or uninstall command and no support claim.
- An Administrator receipt cannot replace the missing ownership model.

## Required design before installation

1. Use a dedicated service identity and protected `ProgramData` state root.
2. Define a one-time, explicit, authenticated enrollment bundle for that
   identity. It must bind the device/control-plane principal, policy and key
   material without copying an interactive user's keychain/profile.
3. Define atomic import, rollback, rotation/revocation, and audit receipts.
4. Attest the fixed service image, no-argument SCM configuration, service DACL,
   state-root DACL, and service identity before enabling broker secret access.
5. Add an opt-in elevated lifecycle receipt that proves install/start/stop/
   uninstall and absence cleanup on a disposable Windows host.

Until every item is implemented and independently evidenced, the dispatcher is
only a contained implementation prerequisite, never proof of a supported
privileged service.
