# E8 Windows privileged boundary

OwnMesh keeps `ownmeshd` in the interactive user's account and runs only the
small privileged broker as a `LocalSystem` SCM service. This avoids copying the
user's enrollment, configuration, or device keys into the SYSTEM profile.

## Installed boundary

- `ownmesh-broker.exe` is installed under the fixed Program Files OwnMesh root
  and runs as the `OwnMeshPrivilegedBroker` SCM service.
- `ownmeshd.exe` is copied into the same protected root but still runs as the
  current-user Scheduled Task.
- The broker Named Pipe DACL admits only SYSTEM, Administrators, and the exact
  installing user SID. The server independently reattests TokenUser, process
  birth, fixed image path, volume/file identity, and SHA-256 before execution.
- The current-user agent can read only the request-MAC secret. The broker
  signing key, replay ledger, staging area, and service configuration remain
  SYSTEM/Administrators-only under ProgramData.
- Every elevated execution is contained in a kill-on-close Job Object and is
  cancelled on timeout, explicit cancel, disconnect, or service shutdown.

The install and uninstall paths are transactional and refuse foreign services,
unexpected DACLs, reparse points, image substitutions, and partial records.
No user profile or keychain migration is performed.

## Operator flow

From an Administrator PowerShell after the normal portable install:

```powershell
ownmesh privileged install
ownmesh service install
```

`ownmesh service install` continues to create a current-user task; it selects
the immutable Program Files daemon image automatically when E8 is installed.

The implementation and Windows-target tests are present. Formal release
evidence still requires running the opt-in Administrator lifecycle receipt on
a disposable native Windows host; cross-compilation alone is not recorded as a
native production receipt.
