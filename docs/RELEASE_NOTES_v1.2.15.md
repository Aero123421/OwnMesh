# OwnMesh v1.2.15

OwnMesh v1.2.15 is a patch release for Linux service-install remediation,
CLI/updater runtime-directory alignment, and Darwin PTY teardown confirmation.
It preserves the v1.2 product surface, the OAuth/passkey model, the MCP
protocol, policy fail-closed guarantees, and the Control Plane storage schema.
The machine-checked contract remains
[`release/SUPPORTED_SURFACES.json`](../release/SUPPORTED_SURFACES.json).

## Fixed

- **`ownmesh service install` remediates OwnMesh-generated systemd leftovers.**
  A leftover `10-ownmesh-workspaces.conf` (or any `# Generated by OwnMesh`
  drop-in that sets `ReadWritePaths=` / other user-namespace-forcing
  directives) is removed on install instead of being left behind by an
  idempotent no-op. Operator-written drop-ins are kept. If the effective unit
  still forces a user namespace, install fails closed and names the remaining
  files. The shipped user unit sets `StartLimitBurst=5` /
  `StartLimitIntervalSec=30` so a custody-fail cannot restart every three
  seconds forever. See [ADR 0011](./adr/0011-systemd-user-sandbox-custody-reconciliation.md).
- **Headless Linux CLI/updater uses the same runtime directory as the user
  service.** When `XDG_RUNTIME_DIR` is unset, discovery uses owner-only
  `/run/user/<uid>/ownmesh` if that directory already exists, instead of
  `state_dir/run`. Update worker and nested `ownmesh status` children receive
  `OWNMESH_CONFIG_DIR` / `OWNMESH_STATE_DIR` / `OWNMESH_RUNTIME_DIR`. This
  is the first slice of #113 (the v1.2.13 → v1.2.14 health-check miss).
- **Darwin PTY Drop/terminate confirms death from the process table.** A
  completed `try_wait` is no longer treated as proof the child is gone when
  `ps` still shows it live. Process-group kill on Darwin uses BSD syntax
  (no GNU `--`).

## Compatibility and migration

- No D1 migration is required.
- Existing OAuth clients, passkeys, refresh tokens, enrolled devices,
  workspaces, policies, sessions, transfers, and ChatGPT connectors remain
  compatible.
- Linux hosts that still have a generated `10-ownmesh-workspaces.conf` should
  run `ownmesh service install` after upgrading. If an operator drop-in still
  forces a user namespace, delete that file by hand and re-run install.
- Authenticode, Apple notarization, MSI/NSIS, and native macOS packages remain
  out of scope.

## Upgrade

1. Run `ownmesh update` or install the signed v1.2.15 archive.
2. On Linux, run `ownmesh service install` if `ownmesh doctor` still reports a
   user-namespace-forcing unit.
3. Confirm `/health/ready` and run `ownmesh doctor --check-network`.

The v1.2.14 release notes remain available for the previous stable patch.
