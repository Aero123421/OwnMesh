# v1.2 E3 — exact-action authorization binding (slice)

## Intent

ChatGPT is the primary runtime action/confirmation UI after one-time CLI/TUI
setup. OwnMesh does **not** receive a cryptographic ChatGPT confirmation
attestation. Instead, the control plane:

1. treats the authenticated, scoped MCP invocation as the exact requested action
2. canonicalizes and hashes that action server-side
3. binds the hash with principal, tenant, device, workspace, operation id,
   expiry, and claim version before dispatch
4. enforces prepare → claim → dispatch → finalize ordering with exactly-once
   side-effect semantics for identical actions

Client-supplied `allow` / `approved` / `force` / `skip_approval` / `principal` /
`policy_result` / `payload_hash` / `risk_level` fields are stripped and are
**never** authority.

## Canonical action + payload_hash

`buildCanonicalAction` / `buildDeviceOperation` (control plane) produce:

```json
{
  "capability": "filesystem.write",
  "action": "fs.write",
  "tool": "ownmesh_fs_write",
  "device_id": "dev_…",
  "principal_id": "prin_…",
  "tenant_id": "ten_…",
  "workspace_id": null,
  "facts": {
    "path": "notes.txt",
    "content_sha256": "…",
    "content_bytes": 12
  }
}
```

`payload_hash` is SHA-256 hex of the stable JSON encoding (sorted object keys).
Write bodies contribute only their digest and byte length so the hash input stays
bounded.

The hash is:

- stored on `mcp_operations` (`payload_hash`, `action_json`, …)
- placed on the device `operation.request` payload
- never accepted from the client as authority

## Idempotency

Lookup key: `(principal_id, tenant_id, device_id, idempotency_key)`

| Prior row | New call | Result |
|---|---|---|
| same hash | identical action | return prior authoritative row (no re-dispatch) |
| different hash | drifted action | `OWNMESH_E_IDEMPOTENCY_MISMATCH` (fail closed) |
| none | fresh | create claim_version=1 and route |

## Bounds retained with this slice

- MCP / DeviceRoom request bodies capped at 1_000_000 bytes before parse
- WebSocket frames rejected before decode when oversized
- Command output streamed into capped rings; limit is visible (`truncated`)
- Cancel kills the process tree and yields terminal `cancelled`
