# v1.2 E3 — exact-action authorization binding

## Intent

ChatGPT is the primary runtime action/confirmation UI after one-time CLI/TUI
setup. OwnMesh does **not** receive a cryptographic ChatGPT confirmation
attestation. Instead, the control plane:

1. treats the authenticated, scoped MCP invocation as the exact requested action
2. canonicalizes and hashes that action server-side
3. binds the hash with principal, tenant, OAuth client, device, workspace,
   operation id, expiry, and claim version before dispatch
4. enforces prepare → claim → dispatch → finalize ordering with exactly-once
   side-effect semantics for identical actions, including crash recovery after
   an accepted claim that never reached DeviceRoom

Client-supplied `allow` / `approved` / `force` / `skip_approval` / `principal` /
`policy_result` / `payload_hash` / `risk_level` fields are stripped and are
**never** authority.

## Canonical action + payload_hash

`buildCanonicalAction` produces **action facts** (stable across identical
retries):

```json
{
  "capability": "filesystem.write",
  "action": "fs.write",
  "tool": "ownmesh_fs_write",
  "device_id": "dev_…",
  "principal_id": "prin_…",
  "tenant_id": "ten_…",
  "oauth_client_id": "client_…",
  "workspace_id": null,
  "facts": {
    "path": "notes.txt",
    "content_sha256": "…",
    "content_bytes": 12
  }
}
```

`bindCanonicalAction` then freezes dispatch ownership:

```json
{
  "...action facts...": true,
  "operation_id": "op_…",
  "expires_at": "…",
  "claim_version": 1
}
```

`payload_hash` is SHA-256 hex of the stable JSON encoding of the **bound**
object (sorted keys). Write bodies contribute only their digest and byte length.

The hash is:

- stored on `mcp_operations` (`payload_hash`, `action_json` = facts only, …)
- placed on the device `operation.request` payload as `payload_hash`
- placed on the device request as `authorization.bound_action` (full bound object)
- never accepted from the client as authority

Immutable expiry is also placed on the DeviceRoom → Agent **envelope**
`expires_at`. Agents reject expired envelopes **and** recompute
`sha256(stable_json(bound_action))` before any side effect, verifying the hash
and that capability/action/device/workspace/operation_id/expires_at/facts match
the live request. Transport authenticity of the control-plane hop is assumed;
OwnMesh does not invent a ChatGPT confirmation attestation.

Mutating MCP tools require a caller-supplied `idempotency_key`. Absent keys are
rejected before route so a lost MCP response can be safely retried.

## Idempotency (atomic claim)

Lookup / ownership key: `(principal_id, tenant_id, device_id, idempotency_key)`

Durable uniqueness: partial unique index `uq_mcp_ops_idempotency`.

API: `claimMcpOperationByIdempotency` — atomic create-or-return.

| Prior row | New call | Result |
|---|---|---|
| same action facts hash, already dispatched/terminal | identical action | return prior authoritative row (no re-dispatch) |
| same action facts hash, `dispatch_outbox.state=pending` | identical action | redeliver the original bound body exactly once, then mark dispatched |
| different action facts | drifted action | `OWNMESH_E_IDEMPOTENCY_MISMATCH` (fail closed) |
| none | fresh | create claim_version=1 with durable dispatch outbox, route, mark dispatched |

Concurrent callers with the same key cannot both insert and both route. The
unique index + claim API ensures a single owner; losers reload and compare
action facts before any device route.

### Crash-safe dispatch outbox

Each accepted claim stores a durable `__ownmesh_dispatch_outbox` object on the
operation row (`state: pending|dispatched` + exact route body). The outbox is:

- written **before** `routeToDevice`
- marked `dispatched` only after DeviceRoom accepts the inject
- redelivered on same-key retry when still `pending` (Worker crash between claim
  and route)
- stripped from every client-facing MCP envelope (`ownmesh_get_operation` and
  tool results never leak the body)

## Cancel is a bound action

`ownmesh_cancel_operation` is **not** exempt from exact-action binding.
The control plane builds a fresh cancel operation with
`authorization.bound_action` facts that include `target_operation_id`.
The Agent live-loop cancel path verifies payload hash, device, expiry, and
target facts **before** `CancelRegistry::cancel`. Unsigned, expired, or
mismatched-target cancels fail closed with
`OWNMESH_E_ACTION_BINDING_MISMATCH` and never signal a process tree.

## Command environment facts

Structured/raw command tools accept an optional `env` object overlay:

- ≤32 entries, key ≤128 B, value ≤4096 B, total ≤16384 B
- keys sorted and bound into `facts.env` / `payload_hash`
- rejected when empty/NUL/`=` keys or non-string values appear
- ownmeshd re-validates and applies the overlay at spawn

## Durable MCP operation quotas

`mcp_operations` is no longer unbounded per tenant:

| Budget | Default |
|---|---|
| rows / tenant | 2_000 (`MCP_OPS_MAX_PER_TENANT`) |
| `data_json` / `action_json` | 256 KiB (`MCP_OPS_MAX_DATA_JSON_BYTES`) |
| terminal result TTL | 7 days → idempotency **tombstone** |
| tombstone TTL | 30 days → hard delete |

Oversized results are visibly truncated (`durable_result_truncated`).
Quota exhaustion returns `OWNMESH_E_MCP_OP_QUOTA`.
Idempotent same-key claims still succeed under quota pressure (replay safety).
Tombstones retain `idempotency_key` / `payload_hash` so completed side effects
are never silently re-run after compaction.

**Unexpired idempotency receipts are never deleted under capacity pressure.**
Only tombstones older than the 30-day window may be hard-deleted. If a tenant
is full of live ops and unexpired tombstones, new distinct operations fail
closed rather than enabling side-effect replay.

## Bounds retained with this slice

- MCP / DeviceRoom request bodies capped at 1_000_000 bytes before parse
- WebSocket frames rejected before decode when oversized
- Server-side clamp of `timeout_ms` (≤300s), `max_output_bytes` (≤1_000_000),
  `max_entries` (≤500), `max_bytes` (≤512_000) before hash/route and again in
  ownmeshd/exec
- Command `env` overlay budgets enforced in MCP sanitize + ownmeshd spawn
- Command output streamed into capped rings; limit is visible (`truncated`)
- Cancel kills the process **tree** (Unix process group / Windows `taskkill /T`)
  only after exact-action verification
- Directory listing scan budget is hard-capped; write uses exclusive randomized
  temp files + parent revalidation (partial E4 TOCTOU hardening)
