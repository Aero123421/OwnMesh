# OwnMesh v1.2 E9 — authenticated resumable transfer

Status: **PROVEN on the local real public path (2026-08-10)**.

E9 is the remote MCP transfer contract. The unsupported `ownmesh transfer *`
CLI placeholders in the surface registry are a separate interface and remain
unsupported.

## Real-path acceptance

[`scripts/tests/test_e9_workerd_transfer.py`](../scripts/tests/test_e9_workerd_transfer.py)
starts and drives this production-shaped path without a mock Agent or direct
runtime IPC:

```text
public /mcp
  -> local Wrangler/workerd + D1
  -> TransferRoom Durable Object
  -> two independently enrolled Agent WebSockets
  -> two real ownmeshd processes
  -> separate state, keychain, workspace and custody roots
```

The fixture proved in one successful run:

- `ownmesh_transfer_plan/send/status/get/list/cancel` through public MCP only;
- 196,873 binary bytes across at least three 64 KiB chunks, including NUL and
  non-UTF-8 bytes, with exact bounded artifact-page reconstruction and SHA-256;
- a zero-byte artifact through the authenticated finish/finish-ack protocol;
- a transfer larger than 32 MiB with the destination Agent stopped after a
  durable non-zero ACK, then restarted with the same durable identity/state;
- fresh epoch/fence restart at Room cursor 65,536 and exact final artifact,
  without restarting at byte zero;
- a separate partial transfer larger than 32 MiB cancelled after durable
  progress, with no destination file or active/retired generation part left;
- no-overwrite behavior and foreign tenant, same-tenant non-owner, device,
  workspace and path-binding denials;
- durable transfer-list parity with status, including owner/tenant exclusion
  and deterministic pagination in both MemoryStore and real SQLite SqlStore;
- destination publication, source cleanup and Room terminal convergence through
  reply-loss/restart-focused product tests.

The measured fixture runtime after the rolling-receiver fix was 99.3 seconds.
The time is evidence only, not an acceptance threshold.

## Durable-state inspection

The fixture stops both Agents and Wrangler/workerd before inspecting storage.
It copies the SQLite main database plus any existing WAL/journal into a writable
snapshot (never copies `-shm`), requires `PRAGMA integrity_check = 'ok'`, then
scans typed cells and raw database bytes.

The scan rejects bearer tickets, raw JTI, device credentials, private ephemeral
material, relay ciphertext/plaintext probes and source payload probes. The only
durable byte content allowed is a user-requested artifact page, and only when
its table/column, maximum 64 KiB page size, SHA-256 and expiry match the strict
allowlist. Logs are scanned under the same secret/payload rules.

## Lower-layer negative coverage

The public MCP client intentionally cannot obtain or substitute raw transfer
tickets, private ephemeral keys or relay frames. The real fixture therefore
does not claim those as public-client fault injections.

The lower layers independently cover wrong/expired/replayed ticket identity,
role/device/tenant/plan binding, ephemeral proof/key substitution, stale fence,
duplicate/gap/overflow frames, tamper/hash mismatch, ACK persistence failure,
late retired-holder writes, generation disk-amplification bounds, save-before-
ACK rollback, reply-loss publication replay and source-cleanup tombstones.
These cases live in the TransferRoom, transport, ownmeshd runtime and
`ownmesh-transfer` focused test suites.
