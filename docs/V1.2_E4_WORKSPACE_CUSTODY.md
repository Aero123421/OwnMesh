# OwnMesh v1.2 E4 — workspace custody (partial)

## Status

**Partial production path.** Restricted-mode filesystem side effects use
handle-rooted custody. Device-local workspace registry + `workspace_id`
selection at the ownmeshd side-effect boundary is implemented and exercised by
the public MCP → workerd → Agent → ownmeshd E2 loopback. CLI workspace CRUD and MCP `ownmesh_workspace_*` device-routed tools are
implemented for the device-local registry. Multi-tenant control-plane workspace
product admin UI remains **out of scope**. The E2–E9 gate stays red until every E4–E9 row is complete.

## What is implemented

### Handle-rooted custody (`ownmesh-fs`, `enforce=true`)

In restricted modes (`workspace_only` / `recommended`):

1. Relative paths are walked as normal components (no absolute / prefix /
   over-climbing `..`).
2. Intermediate directories are opened with no-follow / open-reparse flags and
   must not be symlink or reparse points.
3. The target (or parent for create/write) is opened, then the **opened handle's
   final path** is revalidated against the workspace root
   (`GetFinalPathNameByHandle` on Windows, `/proc/self/fd` on Linux, `F_GETPATH`
   on other Unix) **before** any content is returned or committed.
4. A racing replacement of a regular file with a symlink/junction to an outside
   path fails closed (`SymlinkOrReparse` / `EscapesWorkspace`) and never returns
   outside bytes.
5. **Hardlink / mount policy (fail-closed):** after pathname custody, restricted
   opens reject multi-link inodes (`nlink > 1` / Windows `nNumberOfLinks > 1`)
   and cross-volume device identity (`st_dev` / volume serial mismatch). A
   hardlink placed inside the workspace that aliases an outside file therefore
   cannot be read/written/deleted as authorized content.
6. list / stat / read-range / write (temp+rename) / delete / hash-checked patch
   and git cwd resolution share this custody path.
7. **Directory list holds the open handle** across enumeration (Windows
   handle-rooted `GetFileInformationByHandleEx`, Linux `/proc/self/fd` readdir,
   other Unix `fdopendir`). A rename→symlink replacement of the checked path
   fails closed before any entries are returned.

Full Access / full_user_access (`enforce=false`) keep workspace root as
context/cwd metadata without a hidden path deny; handle final-path pinning is
not required for unrestricted modes.

### Device workspace registry + selection

`ownmeshd` loads `state_dir/workspaces.json` (byte/entry bounded):

- Default id: `ws_default` → `state_dir/workspace`
- Additional roots may be registered with absolute paths and `ws_...` ids
- MCP `workspace_id` is bound into the exact-action hash and propagated into
  runtime FS/git method args so the **selected root** is used at the side-effect
  boundary (not audit-only metadata)
- Unknown `workspace_id` fails closed
- Cross-workspace reads of another root's files fail (not found / no content)

Domain `WorkspaceId` requires the `ws_` prefix on the operation envelope.

### Directory pagination

`list_dir_page` is cursor-resumable: after-cursor candidates are collected up to
a hard ceiling (25_000 in RAM, then durable spool), sorted by `(name, path)`,
then paged under entry and UTF-8 JSON budgets. Aggregate name/path byte budget
is checked **before every append** (not only after full serialize). Durable v2
spool cursors bind `root_key` + `recursive` and reject cross-workspace cursor
substitution. Pages after the first no longer rescan only a fixed first
window (the former 4_000 `scan_budget` trap). A >4_000-entry unit test asserts
every name is returned exactly once across pages.

### Durable local state bounds (related integrity)

`ownmeshd` loads `grants.json`, `approvals.json`, and `revoked-clients.json`
with stat-before-read, file-byte ceilings, and entry/value budgets. Oversized
or corrupt state fails daemon open rather than allocating unbounded input.

## What is intentionally not claimed

| Surface | Status |
| --- | --- |
| CLI `workspace add/list/show/update/remove` | Supported (device-local IPC) |
| Control-plane multi-tenant workspace CRUD product API | Open |

| Dedicated E4-only workerd row promoting registry CLI surfaces | Open (gate remains red) |
