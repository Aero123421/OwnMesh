# v1.2 E1 Agent WebSocket transport

E1 adds the real device-Agent transport needed by later routing epochs. It does
not make remote filesystem, command, approval, workspace, or session operations
a supported product surface.

## Connection and custody

- Only the configured `active_instance` is considered. Multi-instance Agent
  connectivity remains explicitly deferred.
- The existing encrypted/keychain `DeviceCredential` envelope supplies both the
  bearer credential and its issuer/device binding. The Ed25519 device key stays
  in the same secret-store boundary.
- `https://` issuers become `wss://`; the existing configuration validator
  permits cleartext only for loopback issuers, which become `ws://`.
- The request binds `Authorization: Bearer`, the exact issuer origin, role
  `agent`, and the enrolled device ID. Credential material is never formatted
  into tracing output or persisted in transport state.
- TLS uses Rustls with OS-native certificate roots. Incoming messages and frames
  are capped at 1,000,000 bytes.

## Authentication and liveness

1. Agent sends `hello` with `ownmesh.device/1.0`,
   `ownmesh.operation/1.0`, version, and bounded resume metadata.
2. Control plane sends a device-bound challenge message.
3. Agent signs the exact challenge bytes with its stored Ed25519 key and sends
   `proof`.
4. Agent accepts only `accepted` selecting `ownmesh.device/1.0`, then sends
   `ready` with an empty capability list and `remote_routing_enabled: false`.
5. Heartbeat timeout reconnects with capped exponential backoff. Daemon shutdown
   closes the socket and does not leave a reconnect task behind.

## Resume and duplicate handling

`state/agent-transport-state.json` contains no credentials. It durably records:

- the issuer/device binding;
- the next outbound sequence reserved before network send;
- the last accepted control-plane sequence;
- a bounded 4,096-entry inbound message-ID replay window; and
- up to 1,024 terminal correlation replies.

Unknown envelope fields, null expiry, device mismatch, unsafe integers,
non-advancing sequences, invalid operation contracts, and expired requests fail
closed. A repeated completed correlation produces a newly sequenced terminal
reply instead of re-running work or replaying an old WebSocket frame.

## E1 non-claims and remaining gates

- E1 alone does not promote product surfaces. When the Agent is constructed
  without a `DaemonRuntime` handle it still completes requests with
  `OWNMESH_E_UNSUPPORTED_SURFACE` and advertises `remote_routing_enabled: false`.
- E2 wires the production daemon's shared runtime handle and flips readiness;
  see [`V1.2_E2_REMOTE_ROUTING.md`](./V1.2_E2_REMOTE_ROUTING.md).
- The test suite drives a real TCP WebSocket twice through
  hello/challenge/proof/ready and verifies reconnect resume plus correlation
  deduplication.
- `scripts/tests/test_e1_workerd_loopback.py` drives the real debug `ownmeshd`
  binary against local Wrangler/workerd with a temporary D1 and isolated native
  keychain namespace. It proves authenticated ready and sequence resume across
  an actual process restart without accessing a remote Cloudflare resource.
- The live-account E2E is still open.
