# 点検基準（OwnMesh / project）

## コード
- 保守性が高いこと（責務が読み取れる分割、過剰な entangle を避ける）
- 人間が読んで追いやすいこと（意図が名前と構造から分かること）
- マジックナンバーや謎フラグを減らし、必要なら短いコメントで「なぜ」を残す
- 既存スタイルに合わせる。goal と無関係なリファクタを混ぜない
- **実装（コードを書く作業）は Grok 4.5（`xai/grok-4.5` / worker・sfh `pi`）を優先**

## モデル分担（sfh / 調査）
- 実装・編集の主担当: `pi` + `xai/grok-4.5`
- 並列調査・レビュー寄りの codex 既定: `openai-codex/gpt-5.6-sol`
- 必要ならブランチ単位で `gpt-5.6-terra` / `gpt-5.6-luna` に切り替えてよい
- 統合ステップ既定: `openai-codex/gpt-5.6-terra`

## テスト
- 挙動を変えたら、最低限その経路が壊れていないことを確認する
- テストが無い箇所に巨大変更を入れるときは、再現手順か軽い検証をチケットに残す

## セキュリティ
- シークレット・トークン・鍵をコミットしない
- 資格情報をログや成果物に埋め込まない

## スコープ
- goal と無関係なリファクタ・依存追加を混ぜない
- 調査ブランチは `full` access だが、目的外のファイル変更はしない
